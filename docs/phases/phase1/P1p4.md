## Flow-Spezifikation (Wizard)

Der Wizard ist in 5 logische Schritte unterteilt (Steps 1-5). Step 1 (Start) ist implizit und hat keine eigene UI - der User wird direkt zu Step 2 (Beteiligte) weitergeleitet.

> **Hinweis:** Die Exportseite (`/export`) ist nicht Teil des Wizard-Flows, sondern eine separate Abschlussseite nach erfolgreicher Fertigstellung.

### Step 1: Start (implizit, keine UI)
*Anlegen der Deklaration.*
- **Felder:**
    - `procedure`: "EXPORT" (automatisch gesetzt)
- **Operation:** `POST /api/declarations` -> Erstellt Draft, Redirect zu Step 2 (Parties).

### Step 2: Beteiligte (`step=2`)
*Wer versendet und wer empfängt?*
- **Felder (JSON: `parties`):**
    - `exporter.name` (String, Pflicht)
    - `exporter.address.street` (String, Pflicht)
    - `exporter.address.city` (String, Pflicht)
    - `exporter.address.country` (String, ISO 2-stellig, Pflicht)
    - `recipient.name` (String, Pflicht)
    - `recipient.address.street` (String, Pflicht)
    - `recipient.address.city` (String, Pflicht)
    - `recipient.address.country` (String, ISO 2-stellig, Pflicht)
    - `declarant.name` (String, Optional - Fallback auf Exporter)
- **Validierung:** Pflichtfelder nicht leer. Country muss 2 Buchstaben haben.
- **Fehler:** "Bitte geben Sie einen Namen an.", "Ländercode muss 2-stellig sein (z.B. DE)."
- **Operation:** `PATCH /api/declarations/:id` (Update `data.parties`, set `step=2`)

### Step 3: Transport & Allgemeines (`step=3`)
*Wohin geht es und wie?*
- **Felder (JSON: `transport`, `general`):**
    - `general.destinationCountry` (String, ISO 2-stellig, Pflicht)
    - `general.exportCountry` (String, ISO 2-stellig, Pflicht)
    - `transport.mode` (String/Enum, Pflicht: "1" See, "2" Bahn, "3" Strasse, "4" Luft)
    - `transport.identity` (String, Pflicht: Kennzeichen/Flugnummer)
    - `transport.nationality` (String, ISO 2-stellig, Optional)
- **Validierung:** Pflichtfelder.
- **Fehler:** "Bestimmungsland ist Pflicht."
- **Operation:** `PATCH /api/declarations/:id` (Update `data.transport` & `data.general`, set `step=3`)

### Step 4: Warenpositionen (`step=4`)
*Was wird exportiert?*
- **UI:** Liste der Items + "Position hinzufügen" Button.
- **Felder (Pro Item in `declaration_items`):**
    - `description` (String, Pflicht)
    - `commodityCode` (String, Pflicht, 8 Ziffern)
    - `grossMass` (Number, Pflicht, >0)
    - `netMass` (Number, Pflicht, >0)
    - `invoiceAmount` (Number, Pflicht, >=0)
    - `currency` (String, Default "EUR")
- **Validierung:** Mindestens 1 Item muss vorhanden sein, um weiterzukommen.
- **Fehler:** "Bitte erfassen Sie mindestens eine Warenposition.", "Warennummer muss 8-stellig sein."
- **Operation:** Items werden sofort gespeichert via API (CRUD). "Weiter" prüft nur Count > 0 und setzt `step=4`.

### Step 5: Review & Abschluss (`step=5`)
*Prüfen und Fertigstellen.*
- **UI:** Read-only Zusammenfassung aller Daten.
- **Aktion:** "Kostenpflichtig Abschließen" (Simulation).
- **Validierung:** Server prüft erneut alle Pflichtfelder aus Step 1-4.
- **Operation:** `POST /api/declarations/:id/complete`. Setzt `status=COMPLETED`.
- **Erfolg:** Redirect zu `/declarations/:id/export`

### Nach Wizard-Abschluss: Exportseite
*PDF Download (nicht Teil des Wizard-Flows).*
- **Route:** `/declarations/:id/export`
- **UI:** Success Message, Button "PDF Herunterladen".
- **Aktion:** `GET /api/declarations/:id/pdf`

## Routes / Screen-Map

| Route | Beschreibung |
| :--- | :--- |
| `/declarations` | Liste der eigenen Deklarationen (Dashboard) |
| `/declarations/new` | Startet neue Deklaration (redirect -> wizard/1) |
| `/declarations/[id]/wizard/parties` | Step 2: Beteiligte |
| `/declarations/[id]/wizard/transport` | Step 3: Transport |
| `/declarations/[id]/wizard/items` | Step 4: Warenpositionen |
| `/declarations/[id]/wizard/review` | Step 5: Zusammenfassung & Submit |
| `/declarations/[id]/export` | Abschlussseite mit PDF Download (nach Wizard) |

**Navigation:**
- "Zurück": Browser-Back oder Step-Navigation oben.
- "Weiter": Speichert aktuellen Step und navigiert zum nächsten.
- "Speichern & Beenden": Speichert und geht zum Dashboard.

## Was implementiert wurde

### DB & Prisma
- `Declaration` Model (hybrid JSON data)
- `DeclarationItem` Model
- `apps/web/src/server/declaration.ts`: Helper functions für CRUD.

### API
- `POST /api/declarations`: Erstellt Draft.
- `GET/PATCH /api/declarations/:id`: Liest/Updated Draft.
- `POST /api/declarations/:id/items`: Fügt Item hinzu.
- `DELETE /api/declarations/:id/items/:itemId`: Löscht Item.
- `POST /api/declarations/:id/complete`: Validiert und schließt ab.
- `GET /api/declarations/:id/pdf`: Generiert PDF mit `jspdf`.

### UI (Frontend)
- **Dashboard:** `/declarations` mit Liste aller Anmeldungen.
- **Wizard Layout:** Sidebar mit Fortschrittsanzeige, persistent.
- **Screens:** Forms für Parties, Transport, Items (Liste+Add), Review.
- **Validation:** Zod Schemas + React Hook Form für Client-Side Validation.
- **Export:** Success-Page mit PDF-Download Link.

### Docker
- `apps/web/Dockerfile`: Multi-stage build (standalone output).
- `docker-compose.yml`: Startet Web + Postgres + DB Push (Schema Sync für MVP).

### Tests
- **Unit:** `apps/web/test/unit/validation.test.ts` (testet Zod Schemas).
- **E2E:** `apps/web/e2e/wizard.spec.ts` (Click-Flow durch den Wizard).
