## Ergebnis

### Kandidaten-Verfahren
Da im Repository keine spezifischen Verfahren genannt wurden, basieren die Kandidaten auf den im Prompt genannten Beispielen und gängigen Zollstandards:

1.  **IAA (Internetausfuhranmeldung / Export):** Standardverfahren für den Export von Waren.
2.  **IZA (Internetzollanmeldung / Import):** Standardverfahren für den Import (Überführung in den freien Verkehr).
3.  **IPK (Unklar/Platzhalter):** Im Prompt genannt. Mögliche Bedeutung: "Inpassive Veredelung" oder ein spezifisches Steuerportal. Aufgrund Unklarheit als Sekundärkandidat behandelt.

### Auswahlkriterien
1.  **Marktrelevanz:** Wie häufig wird das Verfahren benötigt?
2.  **Demo-Fähigkeit:** Kann in Sprint 1 ein überzeugender "Click-Dummy" mit Speicherfunktion erstellt werden?
3.  **Komplexität:** Vermeidung von komplexen Abgabenberechnungen (Zölle, Steuern) im ersten Wurf.
4.  **Klarer Output:** Verständliches Ergebnis für den User (z.B. PDF-Dokument).

### Bewertung
- **IAA (Export):**
    - *Relevanz:* Hoch (jedes Export-Unternehmen).
    - *Demo-Fähigkeit:* Gut (Formularbasierter Prozess).
    - *Komplexität:* Mittel (Weniger Finanzberechnungen als Import).
- **IZA (Import):**
    - *Relevanz:* Hoch.
    - *Demo-Fähigkeit:* Mittel.
    - *Komplexität:* Hoch (Zollwertberechnung, Abgaben, komplexe Tarifierung).
- **IPK:**
    - *Bewertung:* Ausgeschlossen mangels klarer Definition im Projektkontext.

### Entscheidung
**Hero-Flow = IAA (Internetausfuhranmeldung / Export)**

### Begründung (Warum IAA?)
1.  **Geringere Einstiegshürde:** Export ist logisch oft einfacher strukturiert als Import (weniger Abgabenlogik notwendig für MVP).
2.  **Klarer Use-Case:** "Ich möchte etwas verschicken" ist ein intuitiver Startpunkt für eine Demo.
3.  **MVP-Eignung:** Ermöglicht Fokus auf Datenerfassung, Validierung und Speicherung (Core-Features) ohne komplexe Tarif-Logik.

### Warum nicht IZA / IPK?
- **IZA:** Die Komplexität der Abgabenberechnung und Zollwertfindung sprengt den Rahmen eines ersten "klickbaren" MVP-Sprints, der stabil sein soll.
- **IPK:** Unklare Definition und vermutlich Nischen-Anwendungsfall im Vergleich zu Standard-Export.

### Was wir in Sprint 1 bewusst nicht tun (No-Liste)
1.  **Keine Import-Prozesse (IZA).**
2.  **Keine echte Übermittlung an ATLAS/Zoll:** Nur lokale Speicherung und PDF-Generierung (Mock).
3.  **Keine komplexe Abgabenberechnung:** Keine automatische Steuer/Zoll-Kalkulation.
4.  **Kein User-Management:** Wir nutzen einen Default-Admin/User oder den existierenden `admin@local.test`.
5.  **Keine KI-gestützte Tarifierung:** Manuelle Eingabe von Warennummern.
